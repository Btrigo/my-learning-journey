## 🧠 What I Learned / Key Takeaways

* Software architecture is the intentional organization of a system’s components and responsibilities. More complicated architecture is not automatically better.
* A stateful server stores important data locally, creating problems with failure recovery and scaling. A stateless server keeps persistent data in external systems such as databases or object storage.
* Vertical scaling gives one server more resources, while horizontal scaling adds more server instances.
* A load balancer distributes traffic among healthy server instances. Strategies include round robin, weighted round robin, least connections, health-based routing, and sticky sessions.
* Microservices divide a system into specialized services that can be developed and scaled independently, but they also introduce additional networking, deployment, monitoring, and reliability complexity.
* An API gateway provides a controlled entry point that can authenticate requests, apply policies, and route traffic to the correct internal service.
* Authentication establishes who a user is, while authorization determines what that user is allowed to do.
* Relational databases are suited to structured metadata, while object storage such as Amazon S3 is suited to large files.
* Presigned URLs allow clients to upload files directly to object storage without sending all the file data through the application server.
* Message brokers enable asynchronous communication between services and can provide durable delivery, acknowledgements, retries, fan-out, and dead-letter queues.
* Redis can cache frequently requested metadata in memory, while a CDN caches and delivers file content from locations closer to users.
* Rate limiting protects systems from abuse and excessive resource consumption, commonly returning HTTP `429 Too Many Requests`.
* AI is likely to automate repetitive cloud tasks, but companies will still need people who understand systems, validate AI output, troubleshoot failures, and take responsibility for production decisions.
* My goal should not be to compete with AI at performing manual tasks. I should learn to use AI while developing the knowledge required to recognize when its recommendations are wrong.
* CCNA-level networking knowledge will support my cloud career, but earning the full certification is not currently more important than Linux, AWS, troubleshooting, automation, and hands-on projects.
* My cloud roadmap should begin with strong Linux and networking fundamentals, followed by AWS infrastructure, CDK with Python, CI/CD, automation, Docker, and eventually Kubernetes.
