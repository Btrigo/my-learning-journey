## 🧠 What I Learned / Key Takeaways
- Firewall rules match specific conditions, including direction, protocol, IP address, and port.
- Ping uses ICMP, so a rule blocking TCP port 443 does not block ping. ICMP does not use port numbers.
- During encapsulation, TCP adds a header to create a segment, IP wraps the segment into a packet, and Ethernet wraps the packet into a frame.
- Decapsulation processes those layers in reverse at the receiving endpoint.
- For traffic going to another network, the destination IP identifies the remote host, while the local frame normally uses the default gateway’s destination MAC address.
- Routers remove incoming link-layer framing and create new framing for the next link.
- Connecting to an open TCP port gives access to a listening service; it does not automatically provide a remote shell.
- The service determines the protocol and requests it understands. An HTTP server accepts HTTP requests, not Linux shell commands.
- The Linux shell, the local `telnet>` prompt, and the connected HTTP session are three different environments.
- Ctrl + ] enters the local Telnet client’s command mode. It does not open a shell on the target.
- HTTP requests need correct spacing and a blank line to finish the request headers.
- `200 OK` means the HTTP request succeeded; `400 Bad Request` means the server rejected the request as malformed.
- Successfully identified the lab HTTP server as lighttpd version 1.4.63 and retrieved the flag.
- Linux enumeration commands gather information about the machine where they execute.

### Linux Command Reference — Reviewed for Further Practice
*These commands were discussed; I did not necessarily execute every command.*

- Identity and operating system:
  - `whoami` — current username.
  - `id` — user ID and group memberships.
  - `hostname` — machine name.
  - `hostnamectl` — hostname and system details.
  - `cat /etc/os-release` — distribution and version.
  - `uname -a` — kernel and architecture details.
  - `uname -r` — kernel release.
  - `cat /proc/version` — kernel build information.
  - `uptime` — uptime and load averages.
  - `date` — system date and timezone.
- Hardware and storage:
  - `lscpu` — CPU information.
  - `free -h` — memory and swap usage.
  - `lsblk -f` — disks, partitions, and filesystems.
  - `df -hT` — filesystem capacity, usage, and type.
  - `findmnt` — mounted filesystems.
  - `lspci -nn` — PCI devices.
  - `lsusb` — USB devices.
  - `systemd-detect-virt` — virtualization/container detection.
  - `cat /proc/1/cgroup` — cgroup information and possible container clues.
- Users and permissions:
  - `getent passwd` — account information.
  - `getent group` — groups and memberships.
  - `who` — logged-in sessions.
  - `w` — sessions and activity.
  - `last -n 20` — recent login history, if available.
  - `sudo -l` — commands my account may run through sudo.
  - `pwd` — current directory.
  - `ls -la` — files, ownership, and permissions.
  - `umask` — default permission mask.
- Networking:
  - `ip -br addr` — interface IP addresses.
  - `ip link` — interface status and MAC addresses.
  - `ip route` — IPv4 routes and default gateway.
  - `ip -6 route` — IPv6 routes.
  - `ip neigh` — known local network neighbors.
  - `cat /etc/resolv.conf` — DNS resolver configuration.
  - `resolvectl status` — DNS details where supported.
  - `cat /etc/hosts` — local hostname mappings.
  - `ss -tuln` — listening TCP and bound UDP sockets.
  - `ss -tunap` — sockets and associated processes where permitted.
- Processes, services, and scheduled tasks:
  - `ps auxww` — processes with full command lines.
  - `ps -eo user,pid,ppid,cmd --forest` — process ownership and ancestry.
  - `top` — live process/resource usage; press q to exit.
  - `systemctl --type=service --state=running` — running services.
  - `systemctl list-unit-files --type=service` — service enablement states.
  - `systemctl status SERVICE --no-pager` — inspect a service.
  - `systemctl cat SERVICE` — view its unit configuration.
  - `systemctl list-timers --all` — scheduled systemd timers.
  - `crontab -l` — current user’s cron jobs.
  - `ls -la /etc/crontab /etc/cron.*` — system cron locations.
- Installed software — use the command for the distribution:
  - `dpkg-query -W` — Debian/Ubuntu packages.
  - `rpm -qa` — RPM-based distribution packages.
  - `apk info -v` — Alpine packages.
  - `pacman -Q` — Arch packages.
  - `command -v python3 curl wget nc nmap` — locate available tools.
- Logs and environment:
  - `journalctl -b -n 100 --no-pager` — recent logs from this boot.
  - `journalctl -k -n 100 --no-pager` — recent kernel messages.
  - `ls -lah /var/log` — available log files.
  - `printenv` — environment variables.
  - `printf '%s\n' "$PATH"` — executable search path.
  - `ulimit -a` — shell resource limits.
- Security controls and firewall inspection:
  - `cat /sys/kernel/security/lsm` — active Linux Security Modules.
  - `getenforce` — SELinux mode, if installed.
  - `aa-status` — AppArmor status, if installed.
  - `cat /proc/sys/kernel/randomize_va_space` — ASLR setting.
  - `cat /proc/sys/kernel/yama/ptrace_scope` — ptrace restrictions.
  - `nft list ruleset` — nftables rules.
  - `iptables -S` — iptables rules.
  - `ufw status verbose` — UFW status.
- File permission inspection:
  - `find / -xdev -type f \( -perm -4000 -o -perm -2000 \) -ls 2>/dev/null` — locate SUID/SGID files on one filesystem.
  - `find / -xdev -type d -perm -0002 -ls 2>/dev/null` — locate world-writable directories on one filesystem.
  - `getcap -r /usr /opt 2>/dev/null` — inspect file capabilities.
- Command reminders:
  - Some commands require additional permissions or installed utilities.
  - `2>/dev/null` hides error messages.
  - SUID/SGID files, capabilities, and writable directories are investigation leads, not automatic vulnerabilities.
