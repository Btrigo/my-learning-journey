## 🧠 What I Learned / Key Takeaways

* Computer Management is a central MMC console containing multiple administrative snap-ins.
* Device Manager manages hardware detection and drivers; warning symbols and Device Manager error codes provide evidence about device problems.
* System Configuration (`msconfig`) is primarily a startup-troubleshooting tool, not a general PC-optimization utility.
* Event Viewer is most useful when events are matched to the exact time and symptom of a problem. Normal computers still record warnings and errors.
* Reliability Monitor provides a simpler timeline of crashes, installations, updates, and hardware failures.
* Task Manager provides a quick system overview, while Resource Monitor and Performance Monitor provide deeper measurements.
* Services and startup applications are different: services can run before sign-in, while startup applications generally launch inside a user session.
* Safe Mode, Diagnostic Startup, and a clean boot isolate different parts of Windows.
* Disk Management controls disks, partitions, volumes, file systems, and drive letters. EFI, recovery, OEM, and reserved partitions should not be changed casually.
* Remote Assistance and Remote Desktop are different technologies. Remote access should only be granted to someone trusted.
* DISM repairs the Windows component store, while SFC checks protected system files. Neither is a universal repair command.
* Good troubleshooting follows a repeatable process: define the symptom, determine scope, reproduce it, collect evidence, form a theory, make one reversible change, test, verify, and document.
* A strong technician avoids changing several things simultaneously because that makes the real cause difficult to identify.
* “Latest driver” does not always mean “best driver”; compatibility and the laptop manufacturer’s validated driver matter.
* Help-desk tickets often require understanding several layers at once: the user, application, account, Windows service, driver, hardware, network, and external system.
* Action1 provides endpoint visibility, patching, software deployment, scripting, and remote-management capabilities, but it does not replace foundational knowledge of Windows, networking, Active Directory, or troubleshooting.
