## 🧠 What I Learned / Key Takeaways
- Load balancing isn't one tool — DNS routing, CDN caching, API Gateway, and Kubernetes Services each solve a different slice of the same underlying problem
- Auto Scaling Groups have five distinct policy types (target tracking, step, simple, scheduled, predictive), each suited to different traffic patterns
- Aurora's real innovation is its distributed 6-copy, 3-AZ storage layer — this is what enables fast failover, cheap read replicas, and Aurora-specific features like Backtrack
- Aurora Auto Scaling for read replicas uses a single target-value threshold (not separate scale-out/scale-in values like EC2 ASGs) and runs through Application Auto Scaling, not EC2 Auto Scaling
- No single database option optimizes cost, failover, and auto scaling simultaneously for free — each option trades one against the others
- Elastic IPs are only free while attached to a running resource — an idle allocated Elastic IP incurs cost, a classic cost-optimization gotcha
- Route 53 routing policies (weighted, latency, failover, geolocation, geoproximity, multivalue) can be applied to private hosted zones too, not just public-facing domains
