## 🧠 What I Learned / Key Takeaways
- Git history: BitKeeper → Git in 2005 (Linus Torvalds, after losing BitKeeper access); Git tracks content snapshots, not diffs
- Centralized vs distributed VCS: SVN vs Git; distributed means commit locally first, push explicitly to share
- Cloud VCS: GitHub (2007, oldest) vs GitLab (2014, all-in-one with built-in CI/CD runners/registry/K8s deploy) — GitHub Actions ("Workflows") vs GitLab CI/CD ("runners") are the same underlying concept, different naming
- Environment variables: values stored outside the code, read at runtime via os.Getenv() in Go — this is the practical fix for "Git never forgets" (hardcoded secrets stay in history even after deletion)
- The Go variable name on the left of `=` and the environment variable name string passed to os.Getenv() are two separate things and don't have to match — this was a real sticking point today, resolved by reading the actual file directly instead of guessing
- git fetch (safe, read-only, updates remote-tracking pointer only) vs git pull (fetch + auto-merge into current branch)
- Branching model: branch point → isolated work → merge commit; local main vs remotes/origin/main (a cached pointer, not live)
- Shell quoting: an unescaped apostrophe in a branch name (`brando's-branch`) opens an unterminated quoted string, leaving bash stuck on continuation prompts — not a real error, just broken quoting
- Go doesn't care about whitespace/alignment for code to run (unlike Python); gofmt auto-formats if needed
- Secrets found by digging through git log -p and stale/abandoned branches (git branch -a) rather than commit history alone — real lesson: leftover branches are a genuine secret-leak vector
