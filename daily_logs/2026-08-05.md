## 🧠 What I Learned / Key Takeaways
- Boot chain is a strict handoff sequence: firmware executes bootloader → bootloader reads config and executes OS loader → OS loader loads kernel → kernel takes over and stays running continuously
- ESP (EFI System Partition) is a physical partition holding boot files; BCD is a database file living inside the ESP that stores boot configuration entries
- Secure Boot verifies each stage's digital signature against firmware-trusted certificates before execution — a chain of trust with no equivalent in legacy BIOS
- OS-level concepts map directly onto cloud concepts I already use: permissions ≈ IAM, services ≈ orchestrated deployments, logs ≈ CloudWatch/CloudTrail, processes ≈ containers sharing a host kernel
- Forcing 3 interrupted boots triggers Windows' automatic recovery environment — a legitimate but not risk-free troubleshooting technique
