## 💡 What I Learned / Key Takeaways
- Distinction reinforced: orchestrator (reads/interprets pipeline config, decides what/when) vs. runner/agent (executes the actual job) — runner = build agent
- Fork vs. branch: fork = full independent copy under own namespace (used when you don't own/can't modify the original repo); branch = same repo/permissions, meant to merge back
- GitLab namespace = ownership/location for a project; personal namespace vs. group namespace
- Personal access tokens are how scripts/APIs authenticate as a user instead of using username/password directly — GitLab's API doesn't accept credentials directly
- Public/internal repo visibility on an internally-hosted GitLab instance can leak sensitive data (secrets, API keys) to any registered user, especially when instance registration is left open
- On-merge build toxic combination: if a build auto-triggers on merge requests and any user can fork + edit the CI file (e.g. Jenkinsfile) in their fork, they can achieve RCE on the build agent via a malicious merge request — no approval needed since the webhook fires automatically
- Reverse shell delivery pattern used: host payload via simple Python HTTP server, `curl | sh` inside the Jenkinsfile pipeline step, catch with `nc -lvp`
