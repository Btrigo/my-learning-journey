## 🧠 What I Learned / Key Takeaways

- WSL2 allows me to run an Ubuntu/Linux development environment while Windows 11 remains my main operating system.
- VS Code runs on Windows, but the WSL extension allows the editor, terminal, Git operations, project files, and development tools to operate inside Ubuntu.
- `localhost:<port>` refers to a service listening on a port of the local machine/environment, and VS Code's Ports tab helps expose and manage development services using those ports.
- JavaScript is a programming language originally associated heavily with browsers but can also run outside a browser using Node.js.
- Node.js is a JavaScript runtime. I need it because tools such as the AWS CDK CLI depend on the Node.js ecosystem even if I eventually write CDK infrastructure using Python.
- npm is the Node Package Manager and is used to install/manage Node-based packages and tools.
- NVM stands for Node Version Manager and allows me to install, switch, and manage Node.js versions without relying on Ubuntu's system-provided Node package.
- Installing software successfully is not enough; I should verify the installation, version, and executable location.
- `which <command>` helps identify which executable my shell is actually using.
- My Node.js installation is now located under my NVM directory rather than `/usr/bin/node`, confirming NVM is managing it.
- AWS CDK and Terraform are both Infrastructure as Code tools, but they approach IaC differently.
- CDK can use languages such as Python and ultimately works through AWS CloudFormation, while Terraform primarily uses HCL and maintains Terraform state.
- I want to learn AWS resources manually in the Console and then reproduce important architectures using Terraform and CDK.
- I do NOT need to memorize every installation URL or command. I need to understand the installation sequence, know what each component does, know where to find the official documentation, and know how to verify that each component works.
