## 🧠 What I Learned / Key Takeaways
- SSDLC: cost of fixing a bug scales sharply by phase (design → implementation → testing → maintenance), which is the core justification for shifting security left
- Risk assessment: qualitative (Severity × Likelihood) vs quantitative (ALE = SLE × frequency × ARO)
- Threat modeling: STRIDE (categorize threats, CIA-triad based), DREAD (score threats 0–10 across 5 factors), PASTA (align threats to business objectives)
- SAST/DAST/IAST/RASP distinctions: white box vs black box vs grey box, and where each sits in the pipeline (pre-compile → runtime → production)
- VA vs Pentest: VA is automated/breadth, Pentest actually exploits and chains findings; both run in Operations & Maintenance
- Microsoft SDL vs OWASP S-SDLC, and SAMM (self-assessment against your own risk) vs BSIMM (benchmark against other orgs)
- Pipeline automation shifts the attacker's target from a person's credentials to the pipeline itself
- Git never forgets — deleted secrets still live in commit history; tools like GittyLeaks can dig them out even after a "fix" commit
- Internal vs external dependency risk, reinforced by the Log4Shell case study
- CI/CD elements: trigger → build → test → deploy → deliver; build orchestrator (controls) vs build agent (executes)
- Shared DEV/PROD build agents are a real privilege-escalation path if compromised
- Environment progression (DEV → UAT → PreProd → PROD/DR-HA) and how developer bypasses (e.g. hardcoded OTP) can leak into PROD without proper security gates
- VM architecture: hypervisor manages one host; a separate cluster manager (vCenter, or an EKS control plane) coordinates workload placement across a pool of hosts — this is not traffic load balancing, it's placement/scheduling
- Containers vs VMs: containers share the host OS kernel (no guest OS), which is why they're lighter and faster but more weakly isolated — directly maps to why Kubernetes pods need explicit resource requests/limits
