## 🧠 What I Learned / Key Takeaways
- Hyper-V is a Type 1 (bare-metal) hypervisor, even when managed from a Windows desktop.
- Hyper-V Manager is the management interface. The hypervisor runs beneath Windows, with my everyday Windows installation in a privileged root partition.
- A Type 2 (hosted) hypervisor runs through an existing host operating system. Both types are software.
- A VM has its own virtual hardware, operating system, applications, accounts, and settings.
- Generation 2 provides UEFI firmware and supports Secure Boot and virtual TPM.
- Secure Boot checks startup software. TPM provides separate security functions, such as protecting encryption keys.
- Default Switch connects the VM to a Windows-managed virtual network and provides internet access through the host using NAT.
- The VM can see a virtual Ethernet connection even when my physical desktop uses Wi-Fi.
- An ISO contains installation media. A VHDX is the virtual disk where Windows, applications, and files are stored.
- A dynamically expanding disk’s configured capacity is its maximum size, not its immediate physical storage usage.
- The VM’s virtual C: drive is separate from my physical computer’s C: drive.
- VM disk files remain on the SSD when the VM is off. RAM is released when the VM fully shuts down.
- Windows 11’s minimum disk-capacity requirement is different from the ISO size and initial installed size.
- Windows 11 Pro and Enterprise can both join an Active Directory domain.
- Windows Server will run Active Directory Domain Services and act as the domain controller in our lab.
- Python’s import statement loads an available module; it does not install a missing third-party package.
- Packages installed in Windows are separate from packages installed in WSL Ubuntu.
- A Python virtual environment provides a separate location for a project’s installed packages.
- Creating an environment and activating it are separate steps.
- Activation changes the current shell’s PATH so it selects the environment’s Python.
- My source-code files stay outside .venv.
- sys.argv contains command-line arguments: index 0 is the script name, and index 1 is the first argument after it.
- Checking len(sys.argv) before accessing an argument helps avoid accessing a missing list element.
