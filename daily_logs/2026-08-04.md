## 🧠 What I Learned / Key Takeaways
- An Elastic IP is a static, account-owned public IP decoupled from any one instance's lifecycle — useful mainly for things like NAT Gateways, generally something to avoid reaching for directly in a well-designed architecture (DNS + load balancer usually solves the same problem better)
- Gateways all solve a version of "who can reach whom, and does traffic need to touch the public internet" — picking the right one is about matching the exposure level to the actual requirement
- Reserved Instances/Savings Plans are best matched to the "floor" of predictable, always-on capacity; Spot is for fault-tolerant workloads only
- Aurora's real advantage over standard RDS is architectural (shared storage layer → faster replication, faster failover), not just "a faster version of MySQL/Postgres" — comes at a real cost premium
- Encryption at rest (KMS/envelope encryption) and encryption in transit (SSL/TLS) are completely independent protections — one does not imply the other
- KMS uses a two-tier "envelope encryption" model: a data key does the actual bulk encryption, and that data key is itself encrypted by a master key that never leaves KMS
- SSH key auth (asymmetric, challenge-response, private key never transmitted) and personal access tokens (a bearer secret, not cryptography) solve the same authentication problem in structurally different ways
- Cryptography as a field breaks into three core jobs: confidentiality (encryption), integrity (hashing), and authentication/non-repudiation (signatures) — most confusion comes from not knowing which job a given mechanism is doing
- Older free course material is generally fine for concepts/fundamentals (which don't go stale) but requires verification for specific numbers, current best practices, and newly released features
