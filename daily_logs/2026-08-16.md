## 🧠 What I Learned / Key Takeaways

### Device drivers and Plug and Play

* A driver lets Windows communicate with a device, but one physical device can use an entire **driver stack** rather than one driver.
* Driver-stack components can include:

  * A bus driver that discovers attached devices.
  * A function driver that provides the device’s main functionality.
  * A class driver that supplies standard behavior for a category.
  * Filter drivers that add or modify behavior.
* When hardware is connected, Windows:

  1. Detects it through a bus such as USB or PCIe.
  2. Reads its hardware and compatible IDs.
  3. Searches for matching driver packages.
  4. Ranks the matching packages.
  5. Selects the best trusted match.
  6. Starts the resulting device stack.
* Windows considers driver signature, hardware-ID match, date, and version when ranking packages. The newest-looking version does not automatically win.
* Mice and keyboards are not truly “driverless.” They normally work immediately because Windows already includes generic HID class drivers.
* Vendor drivers add functionality such as pressure sensitivity, macros, lighting, gestures, calibration, firmware updates, and custom buttons.
* A device named `HID-compliant vendor-defined device` is not automatically broken. It may be a legitimate interface within a composite device.
* One physical USB device can appear in several Device Manager categories because it exposes multiple logical functions.
* A virtual machine reports virtual hardware presented by its hypervisor. That explains why a VM can show virtual batteries, disks, network adapters, USB controllers, and displays.

### Device Manager

* Device Manager can be opened with:

```text
devmgmt.msc
```

* A yellow warning symbol means the device has a problem code. The complete status message is found under:

```text
Device Properties → General → Device status
```

* Common problem codes include:

  * Code 10 — Device could not start.
  * Code 22 — Device is disabled.
  * Code 28 — Drivers are not installed.
  * Code 31 — Windows cannot load the required drivers.
  * Code 43 — The device or driver reported a failure.
  * Code 45 — The device is not currently connected.
  * Code 52 — Windows cannot verify the driver’s signature.
* The **Details** tab is especially important for unknown hardware. Useful properties include:

  * Hardware IDs
  * Compatible IDs
  * Device instance path
  * Parent
  * Service
  * Driver INF name
  * Problem code
* The **Events** tab can show when the device was configured, started, migrated, or failed.
* **Scan for hardware changes** triggers another Plug and Play enumeration. It does not repair defective hardware or manufacture a missing driver.
* Disabling a device keeps its installation information but stops normal operation.
* Uninstalling a device removes the current device instance and association.
* Removing the driver package from the Driver Store is a separate and more consequential action.
* Never casually remove storage-controller, chipset, display, network, USB-controller, encryption, or boot-critical drivers.
* Trusted driver-source order:

  1. Computer manufacturer, especially for laptops.
  2. Device manufacturer.
  3. Windows Update.
  4. Approved enterprise or recovery repository.
* Random driver websites and “one-click driver updater” programs are security and stability risks.

### Driver package locations

* A driver package can contain:

  * INF installation instructions
  * A signed catalog
  * Driver binaries
  * Configuration and supporting files
  * Services or user-mode components
* Staging and installation are different:

  * **Staging** adds a validated package to the Driver Store.
  * **Installation** associates a staged package with matching hardware.
* Relevant locations include:

```text
C:\Windows\System32\DriverStore\FileRepository
C:\Windows\System32\drivers
C:\Windows\INF
```

* These locations serve different purposes. Drivers are not simply “all stored in System32.”
* Files should not be manually deleted from the Driver Store.

### Safe device troubleshooting

* A disciplined troubleshooting order is:

  1. Define the exact symptom.
  2. Check power, cables, ports, hubs, and physical connections.
  3. Test another port or known-good cable.
  4. Test the device on another authorized computer.
  5. Record Device Manager status, IDs, version, signer, and events.
  6. Check Windows Update and the manufacturer’s support site.
  7. Restart the application, service, device, or Windows as appropriate.
  8. Roll back a recent driver update when the timing supports that theory.
  9. Reinstall the device carefully.
  10. Remove a driver package only with a replacement and recovery plan.
  11. Review Event Viewer and Reliability Monitor for related failures.
* Restart is often a clearer driver test than Shut down because Fast Startup can preserve some kernel state across shutdowns.

### Windows Registry

* The Registry is a hierarchical configuration database used by Windows, drivers, services, user profiles, and applications.
* It does not contain every setting. Applications may also use files, cloud services, policy stores, firmware, or private databases.
* A Registry **key** resembles a folder.
* A key can contain subkeys and values.
* A Registry value has:

  1. A name
  2. A type
  3. Data
* `(Default)` is the key’s unnamed value. It is not a universal default for every setting.
* Important root keys:

  * `HKCU` — current user’s settings.
  * `HKLM` — computer-wide settings.
  * `HKU` — loaded user-profile branches organized by SID.
  * `HKCR` — merged view of class, file-association, and COM registration.
  * `HKCC` — current hardware-profile configuration.
* `HKCU` maps to the current user’s SID branch beneath `HKEY_USERS`.
* A standard user can normally edit much of HKCU without elevation.
* HKLM is commonly protected and often requires elevation.
* Registry permissions are controlled by ACLs. Even an elevated administrator does not have unlimited access to every protected key.
* Do not take ownership of security-protected keys simply to bypass Access Denied.

### Registry value types

* Common types include:

  * `REG_SZ` — fixed string.
  * `REG_EXPAND_SZ` — string that may contain expandable variables.
  * `REG_MULTI_SZ` — list of strings.
  * `REG_DWORD` — 32-bit integer.
  * `REG_QWORD` — 64-bit integer.
  * `REG_BINARY` — binary data.
* The hexadecimal/decimal choice matters when entering DWORD data.
* `0` and `1` often mean false and true, but this is only a convention. The exact documentation determines their meaning.

### Registry safety and rollback

* Registry Editor can run without administrator elevation. Permissions determine what the user can change.
* Before editing, record:

  * Exact path
  * Value name
  * Type
  * Original data
  * Whether the value existed
  * Expected effect
  * Required restart
  * Authoritative source
  * Rollback method
* A `.reg` export is helpful but is not a perfect snapshot.
* Importing a `.reg` file merges its contents into the Registry.
* It may not:

  * Remove values created after the export.
  * Restore permissions or ownership.
  * Restore every piece of related application state.
* If a value existed before, rollback means restoring its original type and data.
* If it did not exist before, rollback usually means deleting that exact newly created value.
* Export the narrowest relevant key rather than an enormous parent branch.
* Use a VM snapshot, tested backup, or System Restore point before consequential system-wide experiments.
* Do not use Registry-cleaner utilities.

### CLSID and `InprocServer32`

* `CLSID` means Class Identifier and commonly identifies a COM class using a GUID.
* COM registration can control shell extensions, context-menu handlers, file associations, and software components.
* `InprocServer32` identifies an in-process COM server, commonly a DLL loaded inside another process.
* The video’s Windows 11 context-menu tweak relies on undocumented compatibility behavior.
* Undocumented tweaks can stop working after Windows updates.
* The existence of an empty key only matters because specific Windows code checks for it; empty keys are not universally meaningful.
* Explorer may only need to restart for a shell-setting change. Rebooting the entire computer can be unnecessary.

### Windows Security

* Windows Security is primarily a dashboard for multiple protection technologies.
* It can report:

  * Virus and threat protection
  * Account protection
  * Firewall and network protection
  * App and browser control
  * Device security
  * Device performance and health
  * Family options
* A green check mark means the dashboard currently requires no action. It does not prove the system is uncompromised.
* A yellow warning is not proof of infection. It may indicate stale definitions, disabled protection, incompatible drivers, unsupported hardware, or an organizational policy.
* Windows is heavily targeted because it is widely deployed, but market share alone does not determine whether an OS is “dangerous.”
* Security risk depends on likelihood and impact, including exposure, vulnerabilities, user privileges, patching, credentials, monitoring, backups, and recovery capability.
* Windows security follows **defense in depth**. No single layer can prevent every attack.

### Microsoft Defender Antivirus

* Windows Security is the dashboard; Microsoft Defender Antivirus is one of the underlying protection engines.
* Defender can operate in active, passive, disabled, or enterprise EDR-related modes depending on the system.
* Modern Defender uses more than signatures:

  * Real-time inspection
  * Security intelligence
  * Heuristics
  * Behavior monitoring
  * Cloud-delivered protection
  * Automatic sample submission
  * Network protection
  * Potentially unwanted application detection
  * Ransomware controls
* Tamper protection helps prevent attackers from disabling or altering selected security settings.
* Antivirus should not normally be disabled for training demonstrations.
* Installing two full real-time antivirus products can cause conflicts and does not automatically provide twice the protection.

### Defender scan types

* **Quick scan**

  * Checks common malware locations and active areas.
  * Fast but does not inspect every file.
  * A clean result does not prove the entire system is clean.
* **Full scan**

  * Inspects accessible files and active areas more broadly.
  * Can take substantial time and resources.
  * Useful when broader compromise is suspected, but not always the first step.
* **Custom scan**

  * Scans a specific file, folder, removable drive, or suspected location.
  * Useful when evidence points to an exact location.
* **Microsoft Defender Offline scan**

  * Restarts into a trusted scanning environment.
  * Helps detect persistent malware that can hide or interfere while normal Windows is running.
  * Is not automatically “forensics”; it is an endpoint remediation and detection tool.
  * Save work and ensure the BitLocker recovery key is available before recovery-oriented restarts.
* A custom scan can find something that a quick scan did not inspect.
* Detection does not necessarily mean the malware was running. The status and Protection History must be checked.

### Protection History and threat actions

* Protection History can show:

  * Threat detected
  * File blocked
  * File quarantined
  * Removal performed
  * Remediation failed
  * Controlled Folder Access block
  * Potentially unwanted application
  * User-allowed threat
* **Quarantine** isolates the item to prevent normal execution.
* **Remove** attempts to delete or remediate the detected content.
* **Allow on device** creates an exception for the item and can expose the system.
* Allowing a credential-dumping tool such as Mimikatz on a normal computer is extremely dangerous.
* “I know what this tool is” is not enough justification to allow it.
* Security research tools should be handled only in isolated, authorized labs without real credentials, personal data, production access, or trusted-network connectivity.
* Before allowing or restoring anything, verify:

  * Exact file path
  * Hash
  * Digital signature
  * Source
  * Business or lab purpose
  * Whether it executed
  * Whether isolation is adequate
* Quarantine does not prove every related artifact or stolen credential was remediated.

### Firewall, application, and device security

* Windows Firewall performs stateful filtering.
* Unsolicited inbound connections are commonly blocked unless a rule allows them.
* Return traffic for an allowed outbound connection can come back because it belongs to an established flow.
* Outbound connections are often allowed by default, so the firewall alone cannot prevent every malware connection.
* SmartScreen uses reputation and security intelligence to detect suspicious sites, downloads, and applications.
* A signed application is not automatically harmless, and an unrecognized application is not automatically malicious.
* Device Security can report TPM, Secure Boot, virtualization-based security, Core Isolation, and memory integrity.
* Memory integrity uses virtualization-backed protection to enforce stronger integrity checks on kernel-mode code.
* Incompatible drivers can prevent memory integrity from starting.
* Do not delete drivers blindly to remove a warning.
* Never clear the TPM casually because doing so can affect BitLocker, Windows Hello, certificates, VPN credentials, and other protected secrets.

### Ransomware and recovery

* Controlled Folder Access restricts which applications can modify protected files.
* If a legitimate application is blocked, verify it and allow only the exact trusted executable rather than disabling the feature globally.
* Antivirus and ransomware controls do not replace backups.
* A useful backup model is 3-2-1:

  * Three copies of important data.
  * Two different storage types.
  * One copy offline, immutable, or isolated.
* Backups must be tested by restoring data.

## 🛠 Commands / Tools Practiced

### Device and driver tools

```text
devmgmt.msc       Device Manager
eventvwr.msc      Event Viewer
perfmon /rel      Reliability Monitor
msinfo32          System Information
```

```powershell
# List Plug and Play devices
Get-PnpDevice

# Show devices that are not healthy
Get-PnpDevice |
    Where-Object Status -ne "OK" |
    Format-Table Status, Class, FriendlyName, InstanceId

# Show devices by class
Get-PnpDevice -Class "HIDClass"
Get-PnpDevice -Class "Net"
Get-PnpDevice -Class "Display"

# Inspect detailed properties of a known device
$device = Get-PnpDevice |
    Where-Object FriendlyName -like "*Wacom*" |
    Select-Object -First 1

$device | Get-PnpDeviceProperty |
    Format-Table KeyName, Type, Data -AutoSize
```

```cmd
:: Scan for hardware changes
pnputil /scan-devices

:: Enumerate connected or problematic devices
pnputil /enum-devices /connected
pnputil /enum-devices /problem

:: Inventory third-party driver packages
pnputil /enum-drivers
pnputil /enum-drivers /files

:: Inspect one known device and its matching packages
pnputil /enum-devices /instanceid "DEVICE_INSTANCE_ID" /drivers

:: Stage an approved driver package and install it on matching devices
pnputil /add-driver "C:\ApprovedDriver\device.inf" /install

:: Export third-party driver packages
pnputil /export-driver * "D:\DriverBackup"
```

* `pnputil /delete-driver` is powerful and should not be used casually.
* Do not disable or uninstall the active keyboard, mouse, network adapter, USB controller, storage controller, display adapter, or VM integration devices during practice.

### Registry tools

```text
regedit           Registry Editor
```

```cmd
:: Query a safe study key
reg query "HKCU\Software\StudyLab" /s

:: Export the study key
reg export "HKCU\Software\StudyLab" "%USERPROFILE%\Desktop\StudyLab.reg" /y

:: Import the exported data
reg import "%USERPROFILE%\Desktop\StudyLab.reg"

:: Create a string value
reg add "HKCU\Software\StudyLab" /v Theme /t REG_SZ /d Dark /f

:: Create a DWORD
reg add "HKCU\Software\StudyLab" /v ReviewCount /t REG_DWORD /d 3 /f
```

```powershell
# Create a safe per-user lab key
$studyKey = "HKCU:\Software\StudyLab"
New-Item -Path $studyKey -Force

# Create values
New-ItemProperty `
    -Path $studyKey `
    -Name "Theme" `
    -PropertyType String `
    -Value "Dark"

New-ItemProperty `
    -Path $studyKey `
    -Name "ReviewCount" `
    -PropertyType DWord `
    -Value 3

# Read and modify values
Get-ItemProperty $studyKey
Get-ItemPropertyValue $studyKey -Name "Theme"
Set-ItemProperty -Path $studyKey -Name "ReviewCount" -Value 4

# Remove one value
Remove-ItemProperty -Path $studyKey -Name "ReviewCount"

# Verify before removing the lab key
Get-Item $studyKey
Get-ItemProperty $studyKey

# Remove only the explicit lab key
Remove-Item -Path $studyKey -Recurse
```

### Defender and Windows Security tools

```powershell
# Inspect Defender status
Get-MpComputerStatus |
    Select-Object AMRunningMode,
        AntivirusEnabled,
        RealTimeProtectionEnabled,
        BehaviorMonitorEnabled,
        AntivirusSignatureVersion,
        AntivirusSignatureLastUpdated,
        QuickScanAge,
        FullScanAge

# Update Defender security intelligence
Update-MpSignature

# Run scan types
Start-MpScan -ScanType QuickScan
Start-MpScan -ScanType FullScan
Start-MpScan -ScanPath "$env:USERPROFILE\Downloads"

# Defender Offline scan — saves work and restarts the computer
Start-MpWDOScan

# Inspect firewall profiles
Get-NetFirewallProfile |
    Format-Table Name, Enabled,
        DefaultInboundAction,
        DefaultOutboundAction

# Identify active network profiles
Get-NetConnectionProfile

# Inspect TPM and Secure Boot
Get-Tpm
Confirm-SecureBootUEFI
```

* `Get-MpPreference` can expose exclusions and organizational configuration. Review its output before sharing it.
* `Start-MpWDOScan` restarts the computer, so save work first.
* Do not expose BitLocker recovery information in screenshots or copied output.
