## 🧠 What I Learned / Key Takeaways

* Real-time protection continuously inspects files and activity instead of waiting for a scheduled scan.
* Cloud-delivered protection uses current Microsoft threat intelligence, while automatic sample submission helps Microsoft analyze suspicious files.
* Tamper Protection prevents unauthorized applications and malicious scripts from changing important Defender settings.
* Controlled Folder Access blocks untrusted applications from modifying protected folders, helping limit ransomware damage.
* OneDrive version history may assist with recovery, but cloud synchronization is not a replacement for independent, tested backups.
* A strong ransomware strategy includes endpoint protection, least privilege, patching, user education and a 3-2-1 backup strategy.
* Windows Defender Firewall is stateful: it generally permits outbound connections and related return traffic while blocking unsolicited inbound traffic unless a rule allows it.
* Domain, Private and Public are firewall profiles—not separate physical firewalls.
* The Public profile is the most restrictive and should be used on untrusted networks.
* Disabling the entire firewall is usually the wrong solution. A technician should create the narrowest rule required for a program, port, protocol, source and profile.
* A failed ping does not automatically mean a computer is offline. ICMP may be blocked while services such as HTTPS, SMB or RDP remain available.
* SmartScreen evaluates URL reputation, file reputation, download prevalence, digital signatures and cloud threat intelligence.
* Potentially unwanted applications may not be traditional malware but can install unwanted software, alter settings, display excessive advertising or behave unexpectedly.
* Smart App Control can block untrusted applications rather than merely showing a warning.
* Microsoft Defender Application Guard was deprecated and is no longer available beginning with Windows 11 version 24H2.
* Exploit Protection includes mitigations such as DEP, ASLR and Control Flow Guard.
* Core Isolation uses virtualization-based security to separate sensitive security functions from the normal operating system.
* Memory Integrity, also called HVCI, validates kernel-level drivers and code within an isolated environment.
* A TPM can be discrete hardware, firmware-based or virtual. It protects cryptographic secrets and measures the boot environment.
* BitLocker primarily uses symmetric AES encryption, normally XTS-AES 128 or 256.
* BitLocker uses a key hierarchy: the FVEK encrypts drive data, the VMK protects the FVEK, and a TPM, PIN, startup key or recovery key protects access to the VMK.
* BitLocker protects data at rest but does not stop malware from reading files while Windows is running and the volume is unlocked.
* Windows Home may support simplified Device Encryption even though full BitLocker management is primarily associated with Pro, Enterprise and Education.
* DHCP stands for Dynamic Host Configuration Protocol and automatically supplies IP addressing information.
* The DHCP process follows DORA: Discover, Offer, Request and Acknowledge.
* A `169.254.x.x` APIPA address usually indicates that Windows failed to obtain an IPv4 lease from DHCP.
* Static addressing requires a valid IP address, subnet mask, default gateway and DNS-server configuration.
* A DHCP reservation is often preferable to manually assigning a static address because it centralizes management and reduces address conflicts.
* DNS converts hostnames into IP addresses. Successful communication with an external IP but failed hostname resolution strongly suggests a DNS problem.
* Adapter link speed represents the local connection to network equipment, not guaranteed internet speed.
* Professional troubleshooting begins by defining scope: one application, one computer, one location or the entire organization.
* Troubleshooting should proceed outward: adapter → IP configuration → local stack → gateway → internet route → DNS → application port.
* Every diagnostic test proves something specific, but no single test proves that the entire network is healthy.
* Technicians should collect evidence before rebooting, resetting adapters, deleting profiles or resetting the network stack.
* Practical IT work spans endpoints, printers, Active Directory, Group Policy, DHCP, DNS, VPNs, firewalls, Entra ID, Intune, Microsoft 365, Windows Server, virtualization, security and PowerShell.
* The goal is to develop operational judgment through realistic tickets, intentional failures, diagnosis, repair and documentation—not just memorize definitions.

## 🛠 Commands / Tools Practiced

* `ipconfig` — Display basic adapter addressing.
* `ipconfig /all` — Display complete adapter, DHCP, gateway and DNS information.
* `ipconfig /release` — Release the current DHCP lease.
* `ipconfig /renew` — Request a DHCP lease.
* `ipconfig /displaydns` — Inspect the local DNS cache.
* `ipconfig /flushdns` — Clear cached DNS records.
* `ping <address>` — Test ICMP reachability and observe latency or packet loss.
* `ping <address> -t` — Run a continuous ping until stopped with `Ctrl+C`.
* `nslookup <hostname>` — Test DNS resolution.
* `Resolve-DnsName <hostname>` — Test DNS through PowerShell.
* `Test-NetConnection <host> -Port <port>` — Test connectivity to a specific TCP service.
* `tracert <destination>` — Display the Layer 3 path toward a destination.
* `pathping <destination>` — Analyze a route and gather packet-loss measurements.
* `arp -a` — Inspect cached IPv4-to-MAC-address mappings.
* `route print` — Inspect the Windows routing table.
* `netstat -ano` — Display active connections, listening ports and process IDs.
* `Get-NetAdapter` — Inspect adapter status, link speed and MAC addresses.
* `Get-NetIPConfiguration` — Display PowerShell-based network configuration.
* `Get-NetRoute` — Inspect routes through PowerShell.
* `Get-NetNeighbor` — Inspect ARP and IPv6 neighbor information.
* `Get-NetTCPConnection` — Inspect TCP connections and listening sockets.
* `netsh wlan show interfaces` — Examine the current Wi-Fi connection.
* `netsh wlan show drivers` — Review wireless-driver capabilities.
* `netsh wlan show networks mode=bssid` — Inspect visible networks and access points.
* `netsh wlan show wlanreport` — Generate a historical wireless connectivity report.
* `netsh winhttp show proxy` — Inspect the WinHTTP proxy configuration.
