## 🧠 What I Learned / Key Takeaways

- `PATH` is an environment variable containing directories Bash searches when I enter a command.
- `which <command>` helps locate an executable that is found through `PATH`.
- `type -a <command>` can identify aliases, functions, built-ins, and executables, making it more useful than `which` in some situations.
- My `newlog` command is an alias, so Bash replaces it with the full path to the script instead of searching for it through `PATH`.
- `source ~/.bashrc` reloads my Bash configuration into the current shell.
- Linux permissions use `r = 4`, `w = 2`, and `x = 1`, with separate permissions for owner, group, and others.
- In `srw-rw---- root docker`, `root` is the owner and `docker` is the owning group.
- `/var/run/docker.sock` is the Unix socket the Docker CLI uses to communicate with the Docker Engine/API.
- `docker --version` only proves that the Docker CLI exists; `docker info` actually tests communication with the Docker Engine.
- Docker Desktop runs/manages the Docker Engine while WSL integration allows my Ubuntu environment to communicate with it.
- Adding my user to the `docker` group gives my account permission to communicate through the Docker socket.
- Group membership changes may require restarting the WSL session before they take effect.
