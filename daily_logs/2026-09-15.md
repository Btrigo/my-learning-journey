## 🧠 What I Learned / Key Takeaways

* Cloud computing provides computing resources on demand instead of requiring an organization to purchase and maintain all infrastructure locally.
* The cloud is made up of familiar infrastructure components—compute, storage, databases, and networking—delivered as services.
* Managed services reduce the amount of infrastructure administration handled directly by the customer.
* Serverless does not mean that servers no longer exist. It means the cloud provider manages the underlying servers and infrastructure while the developer focuses more heavily on code and application behavior.
* AWS Lambda is an example of serverless compute: developers supply code while AWS handles much of the underlying compute environment.
* Abstraction is a major cloud concept. Higher-level AWS services hide increasing amounts of infrastructure management while still relying on physical servers underneath.
* Scalability allows cloud resources to grow or shrink in response to workload requirements.
* Availability and reliability require intentionally designing systems across appropriate AWS infrastructure rather than assuming that simply using the cloud makes an application resilient.
* The AWS Management Console provides a graphical way to locate, configure, and monitor AWS services.
* The Solutions Architect Associate course is extensive, so completing it will require consistent study sessions rather than trying to absorb everything at once.
* The shorter conceptual video helped provide a mental framework for understanding where individual AWS services fit into the larger cloud-computing model.
