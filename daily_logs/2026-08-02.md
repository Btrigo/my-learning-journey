## 💡 What I Learned / Key Takeaways
- CI/CD pipeline component breakdown: developer workstation → source repo → build orchestrator (GitLab/Jenkins) → build agents (GitLab Runner/Jenkins agent) → environments (dev/prod)
- Orchestrator vs. agent distinction: orchestrator decides what/when, agent actually executes the job
- Namespace in GitLab = ownership/location for a project (personal vs. group); forking to your own namespace claims ownership of the copy
- Fork vs. branch: branch = same repo, same permissions, meant to merge back; fork = full independent copy under your own namespace, used when you don't own/can't directly modify the original
- `.gitlab-ci.yml` basics: jobs assigned to stages (build/test/deploy), jobs in the same stage run in parallel, unstaged jobs default to `test`
