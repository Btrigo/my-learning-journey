## 🧠 What I Learned / Key Takeaways

* WSL2 runs a real Linux kernel in a lightweight virtual machine while Windows remains the host operating system.

* Development repositories should remain inside the native Linux filesystem, such as:

  ```text
  /home/brando/repos/my-learning-journey
  ```

  Keeping active Linux projects outside `/mnt/c` improves performance, permissions, file watching, and tool compatibility.

* My normal project workflow should be:

  ```bash
  cd ~/repos/my-learning-journey
  git pull
  code .
  ```

* Before working in VS Code, I should verify:

  * The lower-left corner says `WSL: Ubuntu-24.04`.
  * The integrated terminal has a Linux prompt.
  * `pwd` begins with `/home/brando/`.
  * `git status` recognizes the expected repository and branch.
  * `which git` returns `/usr/bin/git`.

* VS Code is installed as a Windows graphical application, while Git, Python, AWS CLI, and other development command-line tools are installed inside Ubuntu.

* I do not need Git Bash because WSL provides a more complete Linux environment. PowerShell will be used for Windows administration, while Ubuntu Bash will be used for development.

* An SSH key pair contains:

  * A private key that remains secret on my computer.
  * A public key that can safely be registered with GitHub.

* GitHub uses the public key to verify signatures created by the private key. The private key is never uploaded to GitHub.

* The Git SSH test command is:

  ```bash
  ssh -T git@github.com
  ```

* AWS CLI installation and AWS authentication are separate processes. AWS CLI remains installed even when I am not signed in.

* When I actually need AWS access, my preferred workflow will be:

  ```bash
  aws login
  aws sts get-caller-identity
  ```

* `aws login` uses browser authentication and supplies temporary credentials for up to 12 hours. I do not need to authenticate before every AWS command.

* I can end the temporary AWS session manually with:

  ```bash
  aws logout
  ```

* Persistent Bash aliases are stored in `~/.bashrc`. My `newlog` alias points to:

  ```text
  /home/brando/repos/my-learning-journey/scripts/newlog.sh
  ```

* `ls -l` hides names beginning with a dot, while `ls -la` includes hidden files and directories such as `.bashrc`, `.gitconfig`, `.ssh`, and `.aws`.

* The repository’s `.git` directory contains Git’s internal metadata and should not be manually edited.

* A script can exist and be executable without being directly callable by name. Bash must find it through an alias, function, or directory listed in `$PATH`.
