## 🧠 What I Learned / Key Takeaways

- AWS CDK lets me define AWS infrastructure using a programming language such as Python.

- CDK takes my Python infrastructure code and synthesizes it into CloudFormation.

- The basic workflow I learned is:

  CDK Code
  ↓
  `cdk synth`
  ↓
  CloudFormation Template
  ↓
  `cdk diff`
  ↓
  Review Changes
  ↓
  `cdk deploy`
  ↓
  AWS Resources
  ↓
  `cdk destroy`
  ↓
  Resources Removed

- `cdk list` shows the stacks defined in my CDK application.

- `cdk synth` converts my CDK code into a CloudFormation template. It does NOT deploy anything.

- `cdk diff` compares my local infrastructure definition against what is currently deployed in AWS.

- `cdk deploy` actually applies the infrastructure changes to AWS through CloudFormation.

- `cdk destroy` removes the CloudFormation stack and its managed resources.

- `cdk bootstrap` prepares an AWS account/region with the resources CDK needs for deployments.

- A relatively small amount of CDK code can generate many underlying AWS resources.

- I also reviewed important coding fundamentals:

  - Variable = a name that references a value/object.
  - Function = reusable block of code.
  - Parameter = variable defined by a function.
  - Argument = actual value passed into a function.
  - Return value = information returned by a function.
  - Class = blueprint for creating objects.
  - Object = an instance of a class.
  - Method = function belonging to an object/class.
  - Attribute = information/property belonging to an object.
  - Keyword argument = argument passed using its parameter name.

- Example:

  `my_function = _lambda.Function(...)`

  `_lambda.Function` is the class.

  `_lambda.Function(...)` creates an object.

  `my_function` is the variable referencing that object.

- Example:

  `my_function.add_function_url(...)`

  `my_function` references the Lambda object.

  `.add_function_url()` is a method on that object.

- Example:

  `my_function_url.url`

  `my_function_url` references the Function URL object.

  `.url` accesses an attribute/property of that object.

- `self` refers to the current instance of the class.

- `__init__()` runs when an object is initialized.

- `class HelloCdkStack(Stack)` means my `HelloCdkStack` inherits functionality from the CDK `Stack` class.

- `super().__init__(...)` initializes the parent `Stack` class.

- I learned that my Python CDK code and my Lambda JavaScript code serve different purposes:

  Python CDK code → defines the infrastructure.

  JavaScript Lambda code → runs inside the Lambda.

- I learned that CDK actually executes my Python application. If there is a Python syntax error, CDK commands can fail.

- My `SyntaxError: keyword argument repeated: env` happened because I supplied `env=` twice.

- I learned that a Lambda Function URL can expose a Lambda through an HTTPS endpoint.

- For this lab I used `FunctionUrlAuthType.NONE`, meaning the URL did not require IAM authentication.

- I received a warning that the tutorial's Node.js 20 runtime is deprecated/aging and should be replaced with a currently supported runtime in future projects.
