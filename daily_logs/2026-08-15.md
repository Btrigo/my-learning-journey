## 🧠 What I Learned / Key Takeaways

### 1. Windows identity and authorization

- **Authentication** answers “Who are you?” A password, PIN, smart card, or another credential proves an identity.
- **Authorization** answers “What are you permitted to do?” Windows evaluates group membership, privileges, user rights, and object permissions.
- **Auditing** records selected security activity so an administrator can investigate what happened.
- A successful sign-in does not make a user an administrator. It only means Windows accepted the identity and allowed that type of logon.
- A local account is controlled by the individual computer’s local security authority and commonly appears as `COMPUTERNAME\UserName`.
- Windows internally identifies accounts and groups by security identifiers (SIDs). Renaming an account normally does not change its SID, so its existing permissions continue to apply.
- Groups make access manageable. Administrators grant rights and permissions to a group, then control access by changing group membership.
- The `Users` group provides a normal standard-user baseline. The `Administrators` group provides broad control and should be tightly limited.
- `Remote Desktop Users` contributes the right to sign in through Remote Desktop, but RDP must also be enabled, supported, reachable, and permitted by security policy and firewall configuration.
- A **permission** controls access to an object such as a file. A **user right** controls an operating-system action such as interactive logon. A **privilege** enables a sensitive system operation.
- Use the principle of **least privilege**: give an identity only the access required for its work, for only as long as needed.
- In production, an administrator should ideally use a standard account for daily work and a separate named administrative account for elevation.

### 2. NTFS permissions and effective access

- NTFS files and folders have security descriptors. These can include an owner, a discretionary ACL (DACL), a system ACL (SACL), and inheritance information.
- A DACL contains ACEs. Each ACE identifies a security principal, whether access is allowed or denied, the permitted operations, and how the entry inherits.
- When a process requests access, Windows compares the SIDs and privileges in the process’s access token with the object’s security descriptor.
- Access can come from an ACE assigned directly to the user or through any group in the user’s token.
- Common `icacls` permission codes include:

  - `F` — Full control
  - `M` — Modify
  - `RX` — Read and execute
  - `R` — Read
  - `W` — Write
  - `D` — Delete

- Common inheritance markers include:

  - `OI` — files inherit the ACE (object inherit)
  - `CI` — subfolders inherit the ACE (container inherit)
  - `IO` — inherit only; the ACE propagates but does not apply to the current folder
  - `I` — the displayed ACE was inherited from a parent

- `Modify` is often more useful than separate Read and Write because ordinary work may require renaming and deleting files.
- `/grant` adds permissions to an existing explicit grant, whereas `/grant:r` replaces that identity’s existing explicit grant with the stated permission.
- PowerShell tried to interpret `(OI)(CI)` in the unquoted `icacls` example. Quoting the whole identity-and-permission expression is usually more flexible than using `--%`.
- Explicit Deny can override an otherwise applicable Allow and can make access models difficult to reason about. Prefer granting access only to the correct groups unless a genuine exception requires Deny.
- Ownership is not identical to ordinary access. The owner can generally change permissions; administrators may be able to take ownership as a recovery action.
- For an SMB network share, both share permissions and NTFS permissions apply. The effective result is the most restrictive combination.

### 3. User Account Control

- UAC reduces the risk of applications silently acquiring administrative privileges.
- With UAC enabled, a member of `Administrators` normally runs ordinary applications with a filtered token. Elevation starts a process with the linked full administrative token.
- An administrator usually receives a **consent prompt**: Yes or No.
- A standard user receives a **credential prompt** and must provide the credentials of a separate administrator.
- When a standard user supplies administrator credentials, the elevated program runs in the administrator’s security context. The standard user’s own token is not permanently upgraded.
- This identity change can affect the profile, registry hive, mapped drives, settings, and network resources that the elevated application sees.
- The dimmed UAC screen is the **secure desktop**. Ordinary user applications cannot normally interact with it, which reduces prompt spoofing and automated approval.
- UAC is risk reduction, not a complete guarantee against privilege escalation. Patching, endpoint protection, application control, backups, strong credentials, and least privilege are still required.
- Built-in Remote Desktop can normally display UAC prompts. Some third-party remote-control tools cannot control the secure desktop unless they have an appropriately privileged installed component.
- Core UAC settings are primarily computer-level, although separate policies cause administrators and standard users to experience different prompt behavior.
- Do not type an administrator password into an untrusted installer merely because a user requests it. Verify the program, publisher, source, signature, and purpose first.

### 4. Windows configuration interfaces

- Windows Settings and Control Panel are interfaces to configuration; they are not the configuration itself.
- Settings is the modern interface. Control Panel still exposes legacy applets and detailed configuration that has not been migrated.
- Administrative consoles include Computer Management, Services, Event Viewer, Device Manager, Disk Management, Local Security Policy, and Group Policy Editor.
- PowerShell, native command-line tools, WMI/CIM, the registry, and management policy provide additional administrative layers.
- A **preference** can normally be changed by the user or administrator. A **policy** is enforced and may block changes in Settings.
- Control Panel first appeared in Windows 1.0, not Windows 3.0.
- Useful launch shortcuts include:

  - `control` — Control Panel
  - `compmgmt.msc` — Computer Management
  - `lusrmgr.msc` — Local Users and Groups
  - `secpol.msc` — Local Security Policy
  - `gpedit.msc` — Local Group Policy Editor
  - `services.msc` — Services
  - `eventvwr.msc` — Event Viewer
  - `devmgmt.msc` — Device Manager
  - `diskmgmt.msc` — Disk Management
  - `ncpa.cpl` — Network Connections
  - `sysdm.cpl` — System Properties
  - `appwiz.cpl` — Programs and Features
  - `powercfg.cpl` — Power Options

### 5. Task Manager and performance troubleshooting

- A **program** is executable code stored on disk. A **process** is a running instance with a virtual address space, access token, handles, loaded code, threads, and a PID.
- A **thread** is an individual execution stream inside a process. One process can contain many threads.
- A **service** is a workload controlled by the Service Control Manager. It may run without an interactive user, start on demand, use a dedicated identity, or share a host process such as `svchost.exe`.
- Modern browsers use multiple processes for tabs, extensions, rendering, networking, GPU work, and isolation. Many browser processes do not automatically indicate a problem.
- Task Manager’s Processes page groups related work; the Details page exposes individual executable names, PIDs, users, command lines, elevation state, handles, and threads.
- CPU percentage is relative to total logical processor capacity. A single saturated thread may show only about 6.25% total CPU on a 16-logical-processor system while the application still feels slow.
- High RAM utilization is not automatically unhealthy because Windows uses memory for caching. Warning signs include sustained paging, commit approaching its limit, failed allocations, or a process that continually grows during the same workload.
- Disk percentage primarily reflects active time, not only transfer speed. A slow disk can reach 100% while transferring little data if it is servicing many small, high-latency operations.
- Network throughput does not measure latency, packet loss, DNS delay, wireless interference, or a remote server’s responsiveness.
- GPU activity may represent 3D rendering, compute, video decoding, encoding, or copy work. Hardware video decoding can reduce CPU usage.
- “Not responding” means the application’s UI thread is not processing messages. It may be temporarily busy, blocked on storage/network work, deadlocked, or permanently stuck.
- Ending a task can lose unsaved work or leave files and updates partially written. Close normally first, wait briefly, and terminate only when justified.
- Targeting a PID is safer than terminating by process name because the name-based command may stop every matching instance.
- `explorer.exe` provides much of the interactive shell. Restarting it reloads the desktop and taskbar without rebooting the entire operating system.git 
- Resource Monitor provides more detail about per-file disk activity, network connections, services, handles, and memory behavior.
- Disconnecting another user keeps their session and programs running; signing them off terminates the session and can destroy unsaved work.
- Startup Apps does not show every automatic-start mechanism. Services, scheduled tasks, registry keys, drivers, policy, and application-specific mechanisms can also start software.
- A troubleshooting fix should identify the cause. Killing a process may remove the symptom without correcting the underlying problem.

### 6. System Configuration and startup diagnostics

- The command is `msconfig`, not `msconfig.msc`. System Configuration is an executable, not an MMC snap-in.
- **Diagnostic startup** loads a reduced set of basic devices and services for comparison.
- A **clean boot** runs ordinary Windows while disabling selected non-Microsoft services and startup applications to isolate third-party conflicts.
- **Safe Mode** uses a special minimal driver-and-service configuration.
- **Windows Recovery Environment (WinRE)** provides repair tools when normal startup is unreliable or unavailable.
- These environments are diagnostic conditions, not automatic diagnoses. A disappearing symptom narrows the possible cause but does not prove exactly which component failed.
- During a clean boot, select **Hide all Microsoft services** before disabling the remaining services. Record the original state so it can be restored.
- Efficient isolation uses a half-split or binary-search approach: enable half the candidates, test, and repeatedly divide the suspect set.
- The Services list may contain critical security, encryption, VPN, backup, device-management, and hardware-support software even after Microsoft services are hidden.
- The Boot tab shows entries from the Boot Configuration Data store, not primarily physical boot devices.
- Configuring Safe boot through `msconfig` persists across restarts until reversed. Windows Recovery Environment’s Startup Settings is safer for a one-time Safe Mode boot.
- Safe boot options include Minimal, Alternate shell, Active Directory repair, and Network. Active Directory repair is intended for domain controllers.
- Boot logging writes driver information to `C:\Windows\ntbtlog.txt`. A driver marked as not loaded is not automatically defective.
- Base video helps test graphical startup with basic video behavior. No GUI boot mostly hides the animation and is not a meaningful speed optimization.
- The advanced processor-count and maximum-memory settings are diagnostic restrictions. Windows already uses available processors and memory by default; checking those boxes is not a performance tweak.
- Return to normal configuration after clean-boot testing and verify that security, networking, backup, hardware, and management functions work.

### 7. System information and inventory

- **Inventory** records what is installed. **Monitoring** records what it is doing now. **Diagnostics** investigates faults. **Benchmarking** measures performance under controlled conditions.
- Task Manager provides quick hardware identification and live utilization, while `msinfo32` provides a broader hardware, component, and software-environment snapshot.
- System Information can reveal Windows edition/build, manufacturer/model, processor, firmware, Secure Boot state, memory, boot device, display, storage, network, problem devices, drivers, services, startup entries, and error-reporting records.
- Record the full Windows edition, feature version, build, and architecture. “Windows 11 Pro” alone is not specific enough for troubleshooting.
- BIOS mode and Secure Boot are different. A device may boot in UEFI mode while Secure Boot is disabled.
- Firmware and drivers supply much inventory data. Missing, generic, or inaccurate values are possible.
- A virtual machine reports the virtual hardware presented by the hypervisor, not necessarily the physical host’s hardware.
- Similar desktop and laptop GPU branding does not imply equal hardware or performance. Power limits, cooling, core configuration, VRAM, and sustained clocks matter.
- A physical disk, Windows disk, partition, filesystem volume, and drive letter are related but different objects.
- Specifications alone do not predict performance. Power limits, thermals, firmware settings, memory channels, drivers, background workload, and storage behavior all matter.
- System reports may expose hostnames, usernames, domains, serial numbers, IP/MAC addresses, installed software, running processes, drivers, security products, and crash details. Review and redact before sharing.

## 🛠 Commands / Tools Practiced

### Local users and groups

```powershell
# Create a password as a SecureString
$password = Read-Host "Enter password" -AsSecureString

# Create a local account
New-LocalUser -Name "Bill" -Password $password

# Inspect users and groups
Get-LocalUser
Get-LocalUser -Name "Bill"
Get-LocalGroup
Get-LocalGroupMember -Group "Users"
Get-LocalGroupMember -Group "Administrators"

# Change membership
Add-LocalGroupMember -Group "Users" -Member "Bill"
Add-LocalGroupMember -Group "Administrators" -Member "Bill"
Remove-LocalGroupMember -Group "Administrators" -Member "Bill"
```

### NTFS permissions

```powershell
# Display a folder's ACL
icacls "C:\Lab\goodstuff"

# Grant inheritable Modify permission
icacls "C:\Lab\goodstuff" /grant "Austin:(OI)(CI)M"

# Replace Austin's existing explicit grant
icacls "C:\Lab\goodstuff" /grant:r "Austin:(OI)(CI)M"

# Inspect the ACL as PowerShell objects
$acl = Get-Acl "C:\Lab\goodstuff"
$acl.Owner
$acl.Access | Format-Table IdentityReference, AccessControlType, FileSystemRights, IsInherited
```

### Network configuration and inspection

```powershell
Get-NetAdapter
Get-NetIPConfiguration
Get-NetIPAddress -AddressFamily IPv4
Get-DnsClientServerAddress -AddressFamily IPv4
```

Do not apply a static IP configuration without knowing the correct address, prefix, gateway, DNS servers, and whether the address is available.

```powershell
Get-Service
Get-Service | Where-Object Status -eq "Running"
Get-Service -Name "Spooler"
Get-Service -Name "Spooler" -DependentServices
Get-Service -Name "Spooler" -RequiredServices
Restart-Service -Name "Spooler"
```
