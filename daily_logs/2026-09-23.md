## 🧠 What I Learned / Key Takeaways

-   **Security-group/network permission and SSH authentication are two
    different things.**
    -   Security groups determine whether traffic is allowed to reach
        port 22.
    -   SSH keys prove that the connecting user is authorized.
-   The EC2 instances contain/trust the **public-key side**, while I
    keep the corresponding **private `.pem` keys**.
-   `ssh-agent` is a background process that can hold/use my SSH
    private-key identities for authentication.
-   `eval "$(ssh-agent -s)"` starts an SSH agent and connects my current
    shell to it; it does **not** load keys by itself.
-   `ssh-add` loads private-key identities into the SSH agent.
-   Agent forwarding (`ssh -A`) allows the bastion to use authentication
    provided by my local SSH agent without copying the private EC2
    `.pem` file onto the bastion.
-   The bastion host acts as the controlled entry point into the private
    network.
-   My public IP was allowed to SSH into the bastion, while the private
    EC2 security group allowed SSH specifically from resources using the
    bastion security group.
-   A private EC2 instance does not need a public IPv4 address to access
    the internet outbound when its route table sends internet-bound
    traffic through a NAT Gateway.
-   The NAT Gateway sits in a public subnet and provides outbound
    internet access for resources in private subnets.
-   Successfully receiving responses from `8.8.8.8` proved outbound
    connectivity from the private EC2.
-   `curl -I https://aws.amazon.com` returning `HTTP/2 200` confirmed
    DNS resolution and HTTPS internet connectivity from the private
    instance.
-   AWS resources need to be deliberately torn down after labs,
    especially resources such as NAT Gateways and Elastic IPs that can
    result in unnecessary charges.

## 🛠 Commands / Tools Practiced

### Start an SSH agent

``` bash
eval "$(ssh-agent -s)"
```

### Load EC2 private keys

``` bash
ssh-add ~/.ssh/lab1-ssh-bastion.pem
ssh-add ~/.ssh/lab1-privatew-ssh.pem
```

### View identities loaded into the SSH agent

``` bash
ssh-add -l
```

### Secure EC2 private-key permissions

``` bash
chmod 400 ~/.ssh/lab1-ssh-bastion.pem
chmod 400 ~/.ssh/lab1-privatew-ssh.pem
```

### SSH into the bastion with agent forwarding

``` bash
ssh -A -i ~/.ssh/lab1-ssh-bastion.pem ec2-user@<BASTION_PUBLIC_IP>
```

### SSH from the bastion into the private EC2

``` bash
ssh ec2-user@<PRIVATE_EC2_IP>
```

### Test private-instance internet connectivity

``` bash
ping -c 4 8.8.8.8
```

### Test DNS + HTTPS connectivity

``` bash
curl -I https://aws.amazon.com
```

### Stop the temporary SSH agent

``` bash
ssh-agent -k
```

### Remove disposable EC2 private keys

``` bash
rm -f ~/.ssh/lab1-ssh-bastion.pem
rm -f ~/.ssh/lab1-privatew-ssh.pem
```

### Inspect SSH directory

``` bash
ls -la ~/.ssh
```
